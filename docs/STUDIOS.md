# Studios and missions — format

A **studio** is one interactive page built on one **engine** (a reusable interactive tool). It holds about 4 **missions**. Each mission follows **Explore → Predict → Check → Justify**: the learner manipulates the engine or answers, checks, then explains why in their own words.

The structure is language-neutral. All text lives in per-locale files.

```
content/studios/<studio-id>.yaml                 # structure: engine, concepts, missions, checks
content/locales/<locale>/studios/<studio-id>.json # all text for that studio in one locale
site/src/engines/<engine>.ts                      # the engine (a custom element)
```

## Studio YAML

```yaml
id: frac-what-is
engine: fraction-bars
strand: frac
concepts: [frac.halves-quarters, frac.concept]   # concept-graph ids; grades per curriculum are derived from them
order: 1                                          # position within the strand's studio list
missions:
  - id: shade-three-quarters
    setup:                                        # passed to the engine as its config
      bars: [{ parts: 4, shaded: 0, interactive: shade }]
    check: { type: shaded-equals, value: [3, 4] }
  - id: name-the-fraction
    setup: { bars: [{ parts: 5, shaded: 2, interactive: none }] }
    answer: fraction                              # fraction | integer | decimal | choice: input shown under the engine
    check: { type: answer-equals, value: [2, 5] }
  - id: pounds-and-pence
    locales: [en]                                 # optional: only these locales get this mission
```

## Check types (`site/src/lib/checks.ts`)

| type | passes when | options |
|---|---|---|
| `shaded-equals` | the bar(s) show `value` | `exact: true` also requires the same denominator |
| `point-equals` | every number-line point is on one of `values` | |
| `answer-equals` | the typed fraction equals `value` | `simplest: true`; `denominator: n`; `mixed: true` (must be a mixed number, else `not-mixed`); `traps: [{ value: [2, 1], code: tops-and-bottoms }]` (a known wrong answer gets its own feedback code) |
| `answer-integer` | the typed whole number equals `value` | `traps: [{ value: 74, code: reversed }]` (a known wrong number gets its own feedback code) |
| `answer-decimal` | the typed decimal equals `value` exactly (`value` uses `.` in YAML) | the learner types the locale mark: ۲/۵ (fa-IR), ۲,۵ (fa-AF, ps) or 2.5 (en) |
| `choice` | the chosen option index is `correct` | `options` is a list of placeholders, e.g. `"{{frac:2/3}}"` |
| `steps-correct` | every step of a written method (long division) is right | |
| `counters` | every given condition on the `counters` engine holds, tested in this order: `count` → `marked` → `left` → `equal` → `each` → `colors` → `array`/`rect` → `tree` → `pick` | `count`/`marked`: a total over the zones in `in`, or one entry per zone (`null` = any); `left` (count − marked); `equal` (all zones in `in` the same size); `each: n`; `colors: [red, yellow]`; `array: [rows, cols]`; `rect`; `anyOrder` (colours/array either way round); `tree` (factor tree ends in primes); `pick` (number tapped) with `traps: [{ pick: 3, code: … }]`. Codes: `too-many`/`too-few`, `marked-too-many`/`marked-too-few`, `not-equal`, `wrong-colors`, `wrong-array`, `not-rect`, `tree-unfinished`, `empty` (nothing picked), `too-big`/`too-small` (pick) |
| `place-value` | the number shown on the `place-value` engine equals `value` (a number, or a decimal string such as `"3.45"`) | `canonical: true` (every place holds one digit; else `needs-exchange`); `counts: [14, 2]` (exactly these counts per place, lowest first; else `wrong-counts`); `traps: [{ value: 22, code: took-ten }]`. Other codes: `too-big`/`too-small`, `empty` (nothing shown) |
| `facts-correct` | at least `min` facts were right on the first try in one round of `fact-fluency` (the best round counts) | `min` (default: every fact in the round). Codes: `empty`, `not-finished` (round still going), `too-few` (round over: play again) |
| `measure` | the typed answer (`answer: integer`/`decimal`) or, when nothing is typed, the value set on the `measure` engine (weights on the pan, water poured, needle, arm drawn, units laid) equals `value` | `tolerance: n` (± for estimates); `aligned: true` (the ruler's 0 must be at the object's start / the protractor's baseline on an arm, else `not-aligned`); `traps: [{ value: 6, code: wrote-cm }]`. The engine also reports misreadings for where the tool is now: `not-from-zero` (read the end with the ruler not at 0, or a protractor number when it isn't lined up), `other-scale` (the other protractor scale, 180 − angle). Other codes: `too-big`/`too-small`, `empty` |
| `time-equals` | the clock on the `clock-calendar-money` engine (the first one the learner can change, or `clock: n`) shows `value` (`"7:30"`) | `h24: true` (morning and afternoon differ). Codes: `am-pm` (4:30 for 16:30), `hands-swapped`, `minute-as-number` (7:06 for 7:30), `hour-off-by-one` (8:30 for half past 7), `wrong-hour`, `wrong-minute`, `wrong`, `empty` |
| `date-equals` | the day tapped on the `clock-calendar-money` calendar matches every part given: `day` (a number or `last`), `month`, `year`, `weekday` (0 = Sunday … 6 = Saturday), in the calendar shown | `solar: {…}` / `gregorian: {…}` hold per-calendar rules that override the shared ones. Codes: `empty`, `wrong-year`, `wrong-month`, `off-by-one` (counted the start day), `wrong-week` (right weekday, wrong week), `too-late`/`too-early`, `wrong-weekday` |
| `money-equals` | the purse on the `clock-calendar-money` engine holds `value` | `value` is a number or one per currency (`{ IRR: 1500, AFN: 15, GBP: 15 }`, in toman/afghani/pence); `fewest: true` (as few pieces as the coins on offer allow, else `not-fewest`); `pieces: n` (else `piece-count`); `traps: [{ value: { GBP: 35 }, code: gave-price }]`. Other codes: `too-big`/`too-small`, `empty` |
| `money-compare` | the group of money picked on the `clock-calendar-money` engine has the most (`pick: most`, default) or least (`pick: least`) money, or "same" when all are equal | Codes: `counted-pieces` (picked the group with the most/fewest pieces instead), `not-equal` (said same, they differ), `wrong`, `empty` |
| `shape-board` | every given condition on the `shape-board` engine holds, tested in this order: drawing (`sides`, `shape`/`not`, `area`, `perimeter`, `lengths`) → `count` → `image` → `similar` → `line` → `chord` → `angle` → `points` → `selected` → `cells`/`within`/`net` → `fits` → `piece` → `cubes`/`box` → `pick` | `shape` (inclusive classes: `triangle`…`octagon`, `equilateral`/`isosceles`/`scalene`, `right-angled`/`acute-angled`/`obtuse-angled`, `trapezium` ⊃ `parallelogram` ⊃ `rectangle`/`rhombus` ⊃ `square`, `kite`, `regular`, `convex`/`concave`, `rectilinear`) and `not: [square]`; `sides`; `area`; `perimeter`; `lengths` (any order, ±0.05); `count`; `image: { of, translate \| reflect \| rotate: { about, angle } \| scale: { about, factor } }`; `similar: { of, factor }`; `line: { symmetryOf, parallel, perpendicular, through }`; `chord: true` or `{ diameter: true \| false }` (the last segment has both ends on a compass circle); `angle` (kind or degrees); `points`; `selected`; `cells`, `within`, `net: cube`; `fits` (pieces cover a given shape); `piece: { index, at, turn }`; `cubes`; `box`; `pick`; `traps: [{ shape \| select \| pick \| point, code }]`. Codes: `empty`, `open`, `crossed`, `too-many-sides`/`too-few-sides`, `not-<class>`, `is-<class>`, `area-`/`perimeter-too-big`/`-small`, `wrong-lengths`, `too-many`/`too-few`, `not-image`, `slid` (copied, not mirrored), `wrong-way` (turned the other way), `swapped` (x and y swapped), `not-similar`, `wrong-factor`, `diagonal` (a corner-to-corner line that is no fold line), `not-symmetry`, `not-parallel`, `not-perpendicular`, `not-through`, `no-circle`, `not-chord`, `is-diameter`/`not-diameter`, `is-acute`/`is-right`/…, `angle-too-big`/`-small`, `wrong-point`, `extra`, `missed`, `outside`, `not-net`, `not-fit`, `long-way`, `wrong-turn`, `wrong-place`, `not-box`, `wrong-box`, `too-big`/`too-small` (pick) |
| `problem-canvas` | every condition given for the `problem-canvas` engine holds, tested in this order: `known` → `asked` → `strategy` → `bar` → `table` → `guess` → `list` → `sentence` → `answer` | `known: [ids]` (exactly these facts; `known-missing`/`known-extra`); `asked: id` (`asked-empty`/`asked-wrong`); `strategy: id` or a list (`strategy-empty`/`strategy-wrong`); `bar: { whole, parts, anyOrder, d, more }` with `?` for the unknown (`bar-empty`, `bar-count`, `bar-more`, `bar-whole`, `bar-parts`, `bar-diff`); `table: { cells: [[row, col, value]], follow: col, given: n, list: [[…]], cols, anyOrder }` (`table-empty`, `table-wrong`, `table-pattern`, `list-wrong`, `list-repeat`, `list-missing`); `guess: { found }` (`no-guess`, `not-found`); `list: { keep }` (`crossed-answer`, `too-many-left`); `sentence: { box, uses, solve }` (`sentence-empty`, `sentence-box`, `sentence-numbers`, `sentence-false`, `solve-empty`, `solve-wrong`). A tool check can be a list, one per tool of that kind (`null` skips one); a tool hidden by the chosen strategy fails with `strategy-wrong`. `answer: n` with `traps: [{ value, code }]` (`empty`, `too-big`/`too-small`); the number comes from the engine, else from the studio's `answer: integer` box |
| `chart` | every part given for the `chart-builder` engine holds, tested in this order: `tally` → `typed` → `values` → `level` → `pick` → `chosen` | `tally: [6, 3, 4, 2]` (tally marks per category; `cards-left` = survey cards not yet tallied, `tally-few`/`tally-many`/`tally-wrong` = right total, wrong rows); `typed: [7, 5]` (numbers typed in the «تعداد» column; `count-empty`, `gate-as-four` = a group of five read as 4, `count-wrong`); `values: [6, 3]` (chart values in data units; `key-ignored` = one pictogram symbol / pie sector / grid step per item, `half-needed` = an odd count without the half symbol, `too-high`/`too-low`); `level: true` (levelled bars for the mean; `pool-left`, `not-level`); `pick: apple` or a list (category tapped; `wrong-pick`); `chosen: line` or a list (chart type chosen; `wrong-chart`); `traps: [{ pick \| chosen, code }]`. Also `empty` |
| `pattern` | every part given for the `pattern-machine` engine holds, tested in this order: `complete` → `make` → `unit` → `answers` → `rule` → `layers` → `expr` | `complete: true` (repeat: every slot holds the pattern's item; `not-finished`, `wrong-color` = right shape, `wrong-shape` = right colour, `wrong-item`); `make: true` or n (the learner's own row repeats its unit at least n times, default 2; `one-kind`, `no-repeat`); `unit: true` (the tapped unit is the shortest; `unit-short`, `unit-long`, `unit-repeats` = a multiple of it); `answers: true` or a list of keys (typed numbers: `t4` = term/figure 4, `step` = the jump, `r2` = machine row 2; `wrong-step`, `too-big`/`too-small`); `rule: true` (machine with a hidden rule: the learner's operation and number give every output; `fits-some`, `wrong-rule`); `layers: [{ multiples: 4 }, { factors: 18 }]` (hundred square: exactly these shaded per colour; also `set`, `and`; `missing`, `extra`); `expr: true` (worked to one number in the right order; `not-finished`, `wrong-order`); `traps: [{ key: t10, value: 40, code: four-each }]` or `[{ rule: ['+', 2], code }]`. Also `empty` |
| `chance` | every part given for the `probability-sim` engine holds, tested in this order: `prob` → `space` → `scale` → `chosen` → `trials` | `prob: { outcomes: [red], level: certain }` (or `value: [1, 4]`; levels `impossible`/`unlikely`/`even`/`likely`/`certain`/`possible`) after the learner edits the bag or spinner; `space: true` (the tapped outcomes are exactly the sample space); `scale: true` (every event on the likelihood line at its level); `chosen: blue` (or a list); `trials: 10` (at least that many run); `traps: [{ chosen: red, code: … }, { event: red, level: certain, code: … }, { listed: blue, code: … }]`. Codes: `empty-bag`, `too-likely`/`too-unlikely`, `space-empty`/`space-missing`/`space-extra`, `scale-unplaced`/`scale-high`/`scale-low`, `choose-empty`/`choose-wrong`, `few-trials` |
| `coord` | every part given for the `coord-plane` engine holds, tested in this order: `table` → `points` → `line` → `graph` | `table: "2x + 2"` (every typed y equals f(x); `table-empty`, `table-missing`, `table-wrong`); `points: [[x, y], …]` (exactly these, any order, `tolerance`; `empty`, `too-few`/`too-many`, `swapped` = (y, x) placed, `scale` = squares counted as units on a scaled axis, `one-coordinate`, `wrong-point`); `line: { m, c, x, through, parallelTo, perpendicularTo }` (`m`/`c` a number or `[2, 3]`; `x: 3` = the vertical line; `empty`, `run-over-rise` (m = 1/m), `sign` (m = −m), `scale`, `wrong-gradient`, `not-horizontal`, `vertical`, `not-vertical`, `swapped` (y = 3 for x = 3 or back), `wrong-line`, `intercept-x` (c read where the line crosses the x-axis), `wrong-intercept`, `not-parallel`, `not-perpendicular`, `negative-only` (−m for −1/m), `not-through`); `graph: { f, at }` (the learner's slider graph equals f at the xs `at`, default −3 … 3; `empty`, `wrong-graph`); `traps: [{ point \| cell \| m, c, x, code }]` (tried first) |
| `sets` | every part given for the `discrete-lab` engine holds, tested in this order (a wrong nesting or separation of the ovals is named first): `regions` → `members` → `counts` → `subset` → `shaded` → `written` → `rows` → `table` → `answer` → `probability` | `regions: { A: [2, 4], AB: [6], out: [1] }` (cards per region; regions are named by their sets in order, `out` = inside U, outside the ovals; `cards-left`, `in-both` = a card of both sets in one, `not-a-member`, `is-a-member`, `region-wrong`); `members: { A: [2, 4] }` (`members-missing`/`members-extra`); `counts: { A: 7, AB: 5, B: 3, out: 5 }` (`count-empty`, `count-wrong`); `subset: C⊆B` (`subset-reversed`, `layout-wrong`); `shaded: A − B` (any expression with ∪ ∩ − ′ U ∅ and brackets; `shade-empty`, `outside-missed` = A′ without the part outside every oval, `shade-missing`/`shade-extra`); `written: { A ∪ B: [1, 2, 3] }` (any order; `write-empty`, `overlap-twice` = an element of two sets written twice, `repeat`, `members-missing`/`members-extra`); `rows: true` (every statement row true; `rows-unanswered`, `element-vs-subset` = ∈ for ⊆ or back, `row-wrong`); `table: true` (`table-empty`, `total-wrong`, `table-wrong`); `answer: 15` with `answer: integer` (`empty`, `too-big`/`too-small`); `probability: [5, 20]` with `answer: fraction` (`prob-wrong`). `traps: [{ item: 3, region: A, code }, { count: F, value: 12, code }, { layout: apart, code }, { shaded: A ∩ B, code }, { written: A ∪ B, value: [1, 2], code }, { row: empty, pick: '=', code }, { cell: 't,t', value: 30, code }, { answer: 20, code }]` |
| `solid` | every part given for the `solid-viewer` engine holds, tested in this order: `pick` → `turned` → `unfolded` → `layers` → the typed answer | `pick: bases` (both bases; a side face gives `wrong-base`, one base `one-base`), `pick: base` (one or both), or `pick: [faces]` (`pick-few`/`pick-wrong`); `turned: true` (`not-turned`); `unfolded: true` (`not-unfolded`); `layers: n` or `full` (`layers-empty`, `layers-few`, `layers-many`); one of `volume`/`area`/`lateral`/`length` with `unit` (e.g. `cm3`) and `tolerance` (default 0.01): a right number in the wrong unit gives `area-for-volume` (cm² for a volume), `volume-for-area` (cm³ for an area), `length-unit`, `wrong-unit` or `no-unit`. The engine also reports the classic slips for the quantity asked (`engines/lib/solid-viewer-check.ts` `misreadsFor`): `one-layer`, `no-half` / `wrong-base` (a triangle base without ½, or the face it lies on as the base), `surface-for-volume`, `edges-sum`, `visible-only` (faces in view), `lateral-only`, `one-base`, `volume-for-surface` (e.g. πr²h for a cylinder's side), `total-for-lateral`, `half-around` (πrh), `diameter-for-radius`, `pi-value` (π as 3); then `traps: [{ value, code }]`; else `too-big`/`too-small`, `empty` |
| `algebra` | every part given for the `algebra-tiles` engine holds, tested in this order: `expr` → `simplified` (mat) → `rectangle` → `grid` → `written` → `simplified` (written) | Expressions are ASCII, compared by coefficients (`"3x^2 + 2x - 3"`, `"2(x + 4)"`; Latin letters, `√3` a symbol). `expr` (the mat equals it; `empty`); `simplified: true` (or `mat` / `written`: no zero pairs left on the mat, `zero-pairs`; the typed answer has every kind once, `not-simplified`); `written` (the keypad answer equals it, a number such as `"-5"` too; `empty`, `syntax`); `rectangle: { cells: true }` (every block painted with its tile; `cells-empty`, `wrong-cell`), `rectangle: { sides: [a, b], missing }` (sides in either order; their product is the given tiles, plus `missing` for completing the square; `empty`, `not-given`, `partial-factor` = right area, other sides such as 2(6x + 4), `wrong-sides`); `grid: { rows, cols, cells: true, remainder }` (`headers-empty`, `wrong-header`, `cells-empty`, `added-not-multiplied`, `wrong-cell`, `wrong-total`, `remainder-empty`, `wrong-remainder`); `traps: [{ expr \| write \| sides, code }]`. When no trap matches, a wrong mat or answer is diagnosed: `x-plus-x-is-x2` (2x as x², 3x as x³), `unlike-added` (fewer terms, same coefficient total: 3x + 2 → 5x, 2x² + 3x → 5x³), `sign` (every size right, a sign wrong), `too-big`/`too-small` (numbers), else `wrong-<kind>` for the first kind that differs (`wrong-x2`, `wrong-x`, `wrong-1`, `wrong-xy`). Modules add their own parts to `PARTS` in `engines/lib/algebra-tiles-check.ts` |
| `summary` | every part given for the `chart-builder` `summary` module holds, tested in this order: `ordered` → `marked` → `moved` → typed `median` → `mode` → `range` → `mean` → `mad` → `best` → `compare` | `ordered: true` (the card row is in order, either way; `not-ordered`); `marked: middle` (the median's card, or both middle cards of an even count; `mark-empty`, `unordered-median` = marked before the row is in order, `even-middle` = one of two middle cards, `not-middle`), `marked: mode` (`not-mode`, `mode-missing`), `marked: ends` (`one-end`, `not-ends`) or `marked: [41]` (values, e.g. an outlier; `marked-wrong`); `moved: true` (a value was dragged; `not-moved`); typed `median`/`mode`/`range`/`mean`/`mad`: a number, `true` (whatever the data shows now, after dragging) or one per set (`{ a: 6, b: true }`), `tolerance` (default 0.01) (`empty`, `unordered-median` = the middle of the row as dealt, `even-middle` = one middle value, `mode-is-frequency`, `range-is-max`, `total-only` = the sum for the mean, `median-not-mean`, `signed-deviations` = 0 for the mean deviation, else `too-big`/`too-small`); `best: median` or a list (`best-empty`, `wrong-best`); `compare: { centre: [a, [mean, median], higher] }` (per sentence frame, per slot the accepted options, `null` = any; `compare-empty`, `frame-missing` = a whole frame left out, e.g. averages compared and spread not, `compare-wrong`); `traps: [{ stat, set, value, code }, { best, code }, { frame, slots, code }]` (tried first). Logic: `engines/lib/chart-builder-summary.ts` |

A failed check returns a **reason code** (e.g. `not-simplest`, `too-big`, `wrong-denominator`). The locale file can give specific feedback for a code; otherwise the generic "try again" is shown.

## Locale text JSON

```json
{
  "title": "کسر چیست؟",
  "summary": "…",
  "guide": ["paragraph 1", "paragraph 2"],
  "engine": { "label-point": "نقطه" },
  "missions": {
    "shade-three-quarters": {
      "title": "…",
      "prompt": "…",
      "hint": "…",
      "success": "…",
      "why": "question asking the learner to explain",
      "model": "a model explanation, shown after they write their own",
      "feedback": { "too-big": "…" }
    }
  }
}
```

**`engine`:** labels this studio's engine needs (aria-labels, button text). They reach the engine as `data-*` attributes, e.g. `label-point` → `dataset.labelPoint`. Shared fraction-bar labels live in the UI files.

**Placeholders in text:**
- `{{term:id}}`: a glossary term in the page's locale.
- `{{frac:3/4}}`: a stacked fraction. **Never write a/b inline**, because `/` is the Iranian decimal mark.
- `{{mixed:2 1/3}}`: a mixed number.
- `{{num:2.5}}`: a number with locale digits and decimal mark.
- `{{alg:3x^2 - 2x + 1}}`: an algebra expression or equation (`x = -3`, `(-3)^2`), always left to right with locale digits, − and raised powers; letters stay Latin in every locale (docs/NOTATION.md). Use it for every expression with a letter in RTL text.
- `{{vec:4,2}}`: a coordinate pair or translation vector, x first. fa-IR writes it as a column in square brackets with x on top, as Iran's G6 «محورهای مختصات» and G7 «بردار انتقال» do; fa-AF, ps and en write `(4, 2)` (Afghan G8 «مختصات یک نقطه در مستوی»).
- `{{set:A = [2, 4, 6]}}`: set notation, left to right in every locale, with locale digits: A = {۲, ۴, ۶}. Write braces as `[ ]` (a placeholder cannot hold `}`). Elements are separated by ", ", or by "، " in fa-AF and ps, where "," is the decimal mark. Symbols ∈ ∉ ⊆ ∪ ∩ − ′ ∅ are written as they are: `{{set:4 ∈ A}}`.

**Locale status:**
- fa-IR and en must exist for every studio.
- fa-AF and ps files may be missing (the build falls back to fa-IR in the reviewer preview) or marked `"_status": "draft"`.

## Engine options

- **number-line:** `min`, `max`, `denominator` (ticks per unit), `labels` (`whole`/`all`/`none`), `points` (start points the learner can move), `fixedPoints` (reference points the learner can't move; not part of `state.points`), `addPoints`, `decimal`, `zoom: { from, to }`, `step` (points snap to, and ticks are drawn at, every `step` ticks, e.g. tens on a 200–600 line), `major` (ticks per labelled group: multiples are tall and labelled with `labels: whole`, halves medium, e.g. 10 on 0–100), `jumps: { from, labels }` (hop arcs from the start dot `from` through the movable points in the order placed; `labels` writes each hop's signed size, +۲۰ / −۵), `showValues` (each movable point's value under the line), `instruction` (icon hint + label `instruction-<key>`: `tap`, `hop`). Negative numbers are drawn with the minus on the left (−۴). Labels: `label-line`, `-point`, `-given`, `-clear`.
- **fraction-bars:** see the comments in `site/src/engines/fraction-bars.ts` (`compare`, `keepAmount`, `partsStep`, `given`, `rows`/`tint` area model, `linkParts`).
- **long-division:** `dividend`, `divisor`, `decimals`, `layout` (`auto` = gallows for fa-IR/fa-AF/ps, bus stop for en), `given`.
- **column-arithmetic:** `op` (`add`/`sub`/`mul`), `terms` (top to bottom; decimals as strings, e.g. `"12.5"`; add takes 2 or more, sub/mul 2), `carries` (`type` = the learner writes each carry, default; `show`; `hide`), `carryAt` (`auto` = the studio's `engine.carry` label: `above` the next column for fa-IR/fa-AF/ps, `below` the answer line for en), `placeholder` (long multiplication; `auto` = the studio's `engine.placeholder` label, else `zero`, which Iranian G4, Afghan G4 and UK books all use; `shift` = no zero, row moved left, as in Afghan G3, only when a mission asks for it), `header` (place-value table, «جدول ارزش مکانی»), `inverse` (then check it with the inverse operation on a second sheet, Afghan «امتحان»), `align` (decimals: the last number starts lined up on its last digit and the learner slides it under the mark), `given` (columns already done). Subtraction: the learner taps the top digit on the left to borrow; it is crossed out and its new value written above it (ripples through zeros). Add/sub line up on the decimal mark (shorter decimals padded with muted zeros); mul is right-aligned and the answer has no mark (ask for it with `answer: decimal`). Use `steps-correct`. ## Engine contract

An engine is a custom element `<kg-<engine>>`:
- **Input:** `config` property set from the mission `setup`; `locale` attributes `data-digits`, `data-decimal` and `dir`.
- **Output:**
  - `state` getter: a plain object, e.g. `{ bars: [{ parts: 4, shaded: 3 }] }`.
  - Dispatches `kg-change` whenever the learner changes something.
- **Accessibility:** works with touch (≥44px targets) and keyboard (arrow keys / Enter), and every interactive part has an accessible label.
- **Requirements:**
  - No network.
  - No dependencies beyond the repo.
  - Each engine stays under about 15 KB of minified JS.
  - Lays out correctly in RTL and LTR.
  - Numbers on number lines always increase left → right.

### `fraction-bars`: given cells, area model, linked bars

Options in the mission `setup` (all optional; see `site/src/engines/fraction-bars.ts` for the full list):
- `given: n` on a bar: the first n cells are pre-coloured in a second colour (blue, dotted), as "what you already have". The learner cannot unshade them, and they count as shaded. The −/+ buttons skip part counts that cannot show the given amount exactly (halves: 2 → 4 → 6).
- `rows: r` on a bar: area model. The bar is `parts` columns × `r` rows, and its state reports `parts: rows × columns`. On that bar the −/+ buttons change the rows (`minRows`/`maxRows`, default 1–6) and clear the learner's shading. Label them with `label-fewer-rows` and `label-more-rows` in the studio's `engine` text.
- `tint: n` on an area-model bar: the first n columns are striped (e.g. the ⅔ you take half of). Striped cells do not count as shaded.
- `linkParts: true` at the top level: one set of −/+ buttons re-partitions every bar together.



## Adding an engine (no shared-file edits)
- **Code:** create `site/src/engines/<name>.ts` defining `<kg-<name>>`. It's registered automatically (`site/src/client/engines-registry.ts`). Put pure helpers and their tests in `site/src/engines/lib/`.
- **Styles:** create `site/src/styles/engines/<name>.css`; it's loaded automatically (glob in `layouts/Base.astro`). Use the tokens in `global.css` (`--accent`, `--card`, `--border`, `--shade`, `--ok`, `--no`, `--radius`, …) and logical properties only.
- **Labels:** put them in each studio's locale JSON under `"engine"`, never in the UI files.

## Testing in parallel without collisions
Build into your own folder and serve it on your own port. `scripts/build-isolated.sh <you>` does the build from a snapshot that skips other people's unfinished studios:
```sh
cd site
npx astro build --outDir dist-<you>
npx vitest run
KG_DIST=dist-<you> KG_PORT=<45xx> npx playwright test
```
`dist-*/` is gitignored. Never kill other processes' servers.
